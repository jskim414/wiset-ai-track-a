23차시 · Day 8

GitHub · 발표자료 — 「링크 하나로 증명하기」

오늘 할 일 — 딱 하나
내 프로젝트를 링크 하나로 보여줄 수 있게 만들고, 5분 발표자료 초안까지 만든다.

지난 시간 질문부터 회수합니다

🤔 "채용 담당자가 여러분 이름을 검색하면, 지금은 뭐가 나올까요?"

대부분은 — 아무것도 안 나옵니다. 그게 문제는 아닙니다.
문제는 보여줄 링크가 없다는 것입니다. 오늘 그 링크를 만듭니다.

어제 (Notion) 오늘 (GitHub)
역할 주력 — 읽는 포트폴리오 보조 — 증거 보관소
보여주는 것 성과와 서사 실제 파일 (코드·그래프·README)
채용 담당자에게 "이런 일을 했습니다" "진짜로 했습니다. 여기 있습니다"

그림 3장 — 오늘의 버전
① 3자 분업 문서 초안은 클로드가. "뭘 공개하고 뭘 감출지" 판단은 여러분이 — 오늘 제일 중요한 판단입니다
② 에이전트 오늘은 정리 에이전트 — 내 폴더 전체를 읽고, 내가 한 일을 문서로 정리해 줍니다
③ IPO I my-project 폴더 3주치 → P README·발표자료로 변환 → O 링크 1개 + 슬라이드 초안

오늘 끝나면

  • GitHub · Repo · README가 뭔지 설명할 수 있습니다
  • 내 프로젝트 Repo가 생기고 링크가 생깁니다
  • README를 클로드가 초안 잡고 내가 검수합니다
  • 5분 발표 개요(1슬라이드 1메시지)가 나옵니다
  • 발표자료 초안과 대본 초안까지 완성됩니다
  • 내 목소리로 한 번 리허설을 마칩니다 — 녹음해서 직접 들어봅니다

오늘 꼭 기억할 3가지
🔗 주력은 Notion+PDF, GitHub는 보조 무기 — 링크 하나로 증명한다
🔒 공개 저장소는 전 세계 공개다 — 올리기 전에 판단한다
🎤 1슬라이드 1메시지 — 5분에 여섯 장이면 충분하다

시작하기

바탕화면 → claude-lab → my-project → 주소창 powershell → claude

outputs/ 안에 day8 폴더를 만들어줘.

그리고 scripts/ 와 outputs/ 에 지금까지 쌓인 파일이
각각 몇 개인지 세어서, 종류별로 목록을 정리해줘.

✅ 성공 신호 — 파일 개수와 목록이 나옵니다.

💡 코드를 한 줄도 안 짰는데, 올릴 코드가 이미 있습니다.

3주간 클로드에게 시킨 작업들이 scripts/ 와 outputs/ 에 쌓여 있었습니다.
오늘은 새로 만드는 날이 아니라 이걸 세상에 보여줄 형태로 포장하는 날입니다.

💡 사용량 3원칙 — 이론 시간엔 화면만 보기 · 에러는 다시 던지지 말고 원인부터 묻기 · 차시 끝나면 🧹 /clear.

1부 · 이론 (1시간)

A · GitHub — 왜 하나, 어디까지 하나

솔직하게 말씀드립니다. 자연계열 분석 직무에서 주력은 어제 만든 Notion+PDF입니다.
GitHub는 개발자 채용 기준의 도구입니다. 그런데도 오늘 하는 이유는 둘입니다.

이유
증명 이력서의 "데이터 분석 프로젝트 수행" 옆에 링크 하나 — 말이 아니라 물건으로 증명됩니다
보관 3주치 산출물이 한 주소에 정리됩니다 — 다음 프로젝트도 여기 쌓으면 됩니다

💡 부담 갖지 마세요. 오늘 하는 건 "코딩 도구 GitHub"가 아니라 "파일 보관함 GitHub" 입니다. 전부 마우스로 합니다.

B · 개념은 3개면 됩니다

개념 뜻 비유
Repo(저장소) 프로젝트 폴더의 온라인 버전 내 my-project 폴더를 인터넷에 올린 것
README 저장소 첫 화면에 보이는 설명서 폴더 문 앞에 붙인 안내문
업로드 파일 올리기 드래그 앤 드롭 — 끝

마크다운? — 사실 여러분은 이미 3주째 쓰고 있습니다.
클로드의 답변도, 이 교안도, 어제 만든 포트폴리오 초안도 전부 마크다운입니다. # 는 제목, **굵게**, - 는 목록. 그게 다입니다.

C · README는 6칸이면 됩니다

# 칸 내용
1 프로젝트 목적 어떤 문제를 풀었나 (3~4줄)
2 사용 도구 Python · pandas · Claude Code 등
3 분석 과정 점검→정제→탐색→분석 (불릿 5개 이내)
4 주요 결과 핵심 발견 3개 — 수치 포함
5 발표자료 PDF 링크 (내일 완성본)
6 작성자 이름 · 이메일 · 수행 기간

💡 이 6칸 초안을 클로드가 내 폴더를 읽고 씁니다. 여러분은 사실 검수만 합니다.

D · 5분 발표 — 시간표가 이미 있습니다

구간 시간 내용 슬라이드
문제 30초 어떤 업무를, 왜 자동화했나 1장
데이터·방법 1분 무슨 데이터로, 어떤 순서로 1~2장
결과 2분 그래프 + Before/After 수치 2장
판단·배움 1분 내가 내린 판단, 발견한 함정 1장
다음 30초 다음 단계 + 마무리 1장

피해야 할 5가지 — 채용 담당자가 바로 알아챕니다

□ AI가 만든 걸 검토 없이 그대로 (숫자 틀림 → 즉시 감지)
□ 한 일 전부 나열 (30초 원칙 위반)
□ 수치 없는 결과 ("분석했습니다" ✗ → "731건에서 37건 탐지" ○)
□ 슬라이드 한 장에 메시지 세 개
□ 첫 장에 목차 (5분 발표에 목차는 사치입니다)

2부 · 실습 「링크 하나로 증명하기」 (3시간)

기본 과제는 실습 1~5까지. 여기까지 하시면 오늘 목표 달성입니다.
GitHub 가입이 막히는 분은 실습 4(발표 개요)부터 먼저 하고, 계정은 쉬는 시간에 잡아도 됩니다.

실습 1 · 계정과 저장소 — 전부 마우스로

클로드 없이, 브라우저에서 합니다. 아래는 복사할 프롬프트가 아니라 체크리스트입니다.

□ github.com 접속 → Sign up (개인 이메일)
□ 로그인 후 우상단 + → New repository
□ 이름: 영문-하이픈으로 (예: ai-data-analysis-2026)
□ 설명 한 줄: 업무 데이터 AI 분석 프로젝트 (WISET 2026)
□ Public / Private 선택   ← 잠깐, 아래 판단부터
□ "Add a README file" 체크 → Create repository

🔍 이제 여러분이 판단합니다 — 공개냐 비공개냐

□ Public(공개)   — 채용 담당자가 링크로 바로 봄. 대신 전 세계 공개
□ Private(비공개) — 안전. 대신 링크를 줘도 상대가 못 봄

💡 포트폴리오 용도라면 Public이 기본입니다. 단, 그래서 다음 실습의 "뭘 올릴까" 판단이 중요해집니다.
지금 헷갈리면 Private으로 만들고, 검수 끝난 뒤 Public으로 바꿔도 됩니다 (설정에서 클릭 한 번).

✅ 성공 신호 — github.com/내아이디/저장소이름 주소가 생겼습니다. 이게 여러분의 링크입니다.

실습 2 · README 초안 — 클로드가 내 3주를 정리한다 ⭐ 오늘의 하이라이트

이제 클로드 코드로 돌아옵니다.

내 프로젝트 폴더 전체(data 구조, scripts, outputs)를 읽고,
GitHub 저장소 첫 화면에 올릴 README.md 초안을 한국어로 써줘.

구조는 이 6칸으로:
1) 프로젝트 목적  2) 사용 도구  3) 분석 과정(불릿 5개 이내)
4) 주요 결과(수치 포함)  5) 발표자료(자리만)  6) 작성자(자리만)

- 개인정보나 데이터 원본 내용은 넣지 마
- outputs/day8/README_draft.md 로 저장해줘

✅ 성공 신호 — 6칸이 채워진 초안이 나옵니다.

🔍 이제 여러분이 판단합니다 — 검수의 시간

클로드가 정리한 "내가 한 일" — 읽어보세요. 맞습니까?

□ 숫자가 실제 결과와 일치하는가 (하나라도 다르면 고친다)
□ 내가 기억 못 하던 작업이 있는가 → 있으면 그게 오늘의 발견
□ 과장된 표현이 있는가 → 있으면 뺀다

💡 3주간 배운 "검수"의 최종 시험이 이겁니다.

코드 검수(Day 2), 결과 검수(매일), 그리고 오늘 — 나에 대한 문서 검수.
AI가 만든 걸 그대로 올리는 사람과, 검수해서 올리는 사람. 채용 담당자는 이 차이를 정확히 알아봅니다.

실습 3 · 올릴 것과 올리지 않을 것

업로드 전, 오늘의 핵심 판단입니다.

내 폴더의 파일들을 GitHub 공개 저장소에 올려도 되는지 분류해줘.

- data/raw/ 의 원본 데이터
- data/processed/ 의 정제본
- scripts/ 의 코드
- outputs/ 의 그래프와 표

각각 올려도 되는지, 왜 그런지 알려줘.
개인정보·라이선스 관점도 짚어줘. 최종 판단은 내가 할게.

🔍 여러분의 결정

□ scripts/ 코드        → 보통 올린다
□ outputs/ 그래프·표    → 보통 올린다 (개인정보 없는지 눈으로 확인)
□ 원본 데이터          → 보통 안 올린다 — README에 "출처 링크"로 대체
□ 내 업무 데이터       → 🔴 공개 저장소에는 올리지 않는다

🔴 공개 저장소 = 전 세계 공개 + 사실상 회수 불가.

한 번 올라간 파일은 지워도 기록이 남습니다. 데이터는 링크로, 결과는 파일로 — 이게 안전한 기본값입니다.

판단이 끝났으면 — 브라우저에서 업로드

□ 저장소 → Add file → Upload files
□ 올리기로 정한 파일들 드래그 앤 드롭 → Commit changes
□ README.md 열기 → 연필(✏️) → 실습 2 초안 붙여넣기 → Commit

✅ 성공 신호 — 저장소 첫 화면에 내 README가 보입니다. 휴대폰으로 링크를 열어 확인해 보세요.

실습 4 · 5분 발표 개요

README와 outputs/ 를 바탕으로 5분 발표 개요를 만들어줘.

- 슬라이드 6~8장, 1슬라이드 1메시지
- 구성: 문제(30초) → 데이터·방법(1분) → 결과(2분)
        → 판단·배움(1분) → 다음(30초)
- 각 장에 들어갈 그래프 파일명도 지정해줘

outputs/day8/ 에 저장해줘.

✅ 성공 신호 — 장별 메시지 + 그래프 배치가 정해진 개요.

실습 5 · 슬라이드 만들기 — AI에게, 그리고 검수

개요를 슬라이드 도구에 붙입니다. Gamma(감마) 또는 ChatGPT — 어느 쪽이든 됩니다.

□ gamma.app 접속 → 새로 만들기 → "텍스트로 붙여넣기"
□ 실습 4의 개요 전체 붙여넣기 → 생성
□ 나온 슬라이드를 개요와 대조 — 장수·메시지가 유지됐는가
□ 그래프 자리에 outputs/ 의 실제 그림으로 교체

✅ 성공 신호 — 슬라이드 초안 6~8장.

🔍 이제 여러분이 판단합니다

AI가 만든 슬라이드에서, 고쳐야 할 것을 찾아보세요.

□ 숫자가 내 결과와 다르지 않은가   ← 가장 흔한 사고
□ 안 한 일이 들어가 있지 않은가
□ 디자인은 예쁜데 메시지가 사라지지 않았나

💡 Gamma가 안 되면 — ChatGPT(또는 클로드)에 개요를 주고 "장별 제목+본문 3줄" 로 받아 PPT에 직접 붙이면 됩니다. 도구는 수단입니다.

outputs/day8/ 에 저장해줘.

⚡ 심화 과제

심화 1 · 두 집을 잇기

□ Notion 포트폴리오에 GitHub 링크 추가
□ GitHub README 6번 칸에 Notion 링크 추가
□ 이력서(초안)에 넣을 줄: "포트폴리오: [Notion 링크] · GitHub: [저장소 링크]"

심화 2 · README 고도화

README에 프로젝트 폴더 구조를 그림처럼 보여주는 섹션과,
대표 그래프 1장이 첫 화면에 보이도록 이미지 삽입 문법을 추가해줘.

심화 3 · 링크 옆에 붙일 한 줄

이력서에서 GitHub 링크 바로 옆에 붙일 소개 문장 1개를 써줘.
"무엇을 자동화한 프로젝트인지 + 수치 하나"가 들어가게.
20자 안팎 버전과 40자 안팎 버전 두 개.

💡 심화 3은 모든 분께 권합니다. 링크만 덜렁 있는 이력서와, 한 줄 설명이 붙은 이력서 — 클릭률이 다릅니다.

2) 5분을 넘으면, 어디를 잘라야 하는지 우선순위로 3개 알려줘
   (버릴 것부터. 결과 부분은 되도록 건드리지 마)
3) 첫 30초 안에 "무슨 문제를 풀었는지"가 나오는지 판정해줘

✅ 성공 신호 — 분량 추정 + 자를 곳 3개 + 첫 30초 판정. 5분을 넘는다고 나오면 지금 자릅니다.

② 혼자 소리 내어 리허설 — 녹음하면서 ⭐ 오늘의 마지막 관문

머릿속 리허설은 리허설이 아닙니다. 소리를 내야 진짜 시간이 나옵니다.

□ 휴대폰 녹음(또는 녹화) 켜기
□ 타이머 켜고 슬라이드 보면서 실제로 발표 — 처음부터 끝까지, 멈추지 않고
□ 끊겨도 다시 시작하지 말고 그냥 이어서 갈 것 (실전도 그렇습니다)

💡 주변이 신경 쓰이면 — 복도·계단·빈 강의실 어디든 됩니다. 작은 소리로라도 입 밖으로 내면 됩니다. 속으로 읽는 것과 시간이 완전히 다릅니다.

🔍 이제 녹음을 들으면서 여러분이 채점합니다

내가 한 발표를 내가 처음으로 듣습니다. 남이 지적해 주는 것보다 정확합니다.

□ 5분 안에 끝났는가          → 초과면 몇 분 몇 초: ______
□ 첫 30초에 "무슨 문제를 풀었는지" 나왔는가
□ 끝나고 기억나는 숫자가 하나 있는가
□ 목소리가 뒤로 갈수록 작아지지 않았는가
□ 내가 듣기에 어디가 제일 지루했는가 → ______   ← 여기를 자릅니다

💡 다섯 번째 칸이 핵심입니다.

내가 들어서 지루한 부분은 남이 들으면 두 배로 지루합니다. 거기가 잘라낼 곳입니다.

시간이 넘었다면 — 자르고 한 번 더

□ 위 5번에서 지목한 부분 삭제
□ 다시 녹음하며 한 번 더 — 두 번째가 항상 낫습니다

③ 강사 피드백 + 내일 안내

  • 막힌 분 위주로 강사 순회 1:1
  • 내일까지 할 일 — 슬라이드 마무리 · 첫 문장 연습 · 발표 파일을 USB 또는 이메일로 백업

⚠️ 내일 발표는 화면 캡처로. 라이브 시연은 네트워크·사용량 변수가 큽니다. 오늘 결과 화면을 미리 캡처해서 슬라이드에 넣으세요.
